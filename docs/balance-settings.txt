Оновлено 2026-08-08 (гілка feat/externalize-balance-config): усі колишні
Java-константи балансу винесено в application.yml (секція balance.*) —
колонка "ДЕ" тепер вказує на неї замість конкретного .java-файлу.
Це знімок поточних ЕФЕКТИВНИХ значень (після всіх V1-V22 міграцій) — не
історія змін. Де саме кожне число редагувати — колонка "ДЕ" праворуч.

Формат: якщо значення живе в БД (Flyway-контент) — редагувати НОВОЮ
міграцією (db/migration/{h2,postgresql}/V{N}__*.sql, обидва вендори).
Якщо в application.yml (balance.*) — редагувати YAML напряму (dev і prod
читають той самий файл, application-prod.yml його не перевизначає) і
не забути продублювати зміну в src/test/resources/application.yml
(той файл повністю ЗАТІНЯЄ, а не зливає, основний application.yml для
@SpringBootTest — розділ 11 CLAUDE.md). Реальні фізичні константи
(BindingEnergy/SEMF) — виняток, лишаються Java-кодом (НЕ балансний важіль).

Формули ефектів (UpgradeMultipliers.java, engine/ — тепер @Component-бін,
не статичний утиліті-клас; коефіцієнти нижче з application.yml):
  ENERGY_MULT       1 + value * effective_level (softcap після рівня 20,
                     balance.upgrade-multipliers.energy-mult-softcap-threshold = 20)
  GENERATOR_MULT    1 + value * level
  COST_SCALE_REDUCE max(MIN_COST_MULTIPLIER, baseMult - value*level)
                     — balance.generator.min-cost-multiplier = 1.03
  CRYSTAL_GAIN      1 + value * level
  CORE              10^softcap(level * value * log10(VC))
                     softcap-стеля: core-exp-softcap=60.0 + core-exp-range=40.0
                     = 100 (tanh-асимптота, макс буст ~1e100)
                     ДЕ: application.yml, balance.upgrade-multipliers.*
  ENERGY_POW        rate^(1 + value*level), лише якщо rate > 1
  PHANTOM_GEN       rate *= (1 + bonus), покриває 2*level генів
  AUTOBUY           перші level генів купуються щосекунди

Ці ж @Scheduled-методи (GameEngine.tick, AutoBuyService, AutoSynthesizeService,
AutoUpgradeService, StarService) читають свій інтервал через
fixedRateString = "${balance.xxx.interval-ms}" — НЕ через компайл-тайм
Java-константу в анотації, тому редагування application.yml міняє темп тіку
без recompile.
